# External Benchmark Results

Independent, real-world datasets that codelang-detect was never tuned against —
used to sanity-check the 100%-accuracy claim from the curated 60-sample suite
(`benchmark/test_data.json`).

Run with `benchmark/benchmark_external.py` (see `SAMPLES_PATH` / `DATASET_NAME`
env vars). Sample corpora are generated by `benchmark/fetch_codesearchnet.py`
(CodeSearchNet) and a one-off extraction script against the smola dataset repo
(not checked in here — the corpus lives outside this repo at
`C:\Repos\language-dataset\samples.jsonl`, since it's third-party data, not
project code).

## 1. smola/language-dataset

Real GitHub files, human-reviewed labels, restricted to the 24 languages
codelang-detect supports. 453 samples, 24 languages.

| Library | Accuracy | Macro-F1 | µs/sample |
|---|---:|---:|---:|
| **codelang-detect (ours)** | **75.7%** | **0.733** | 27,299 |
| Pygments | 14.8% | 0.113 | 16,384 |
| WhatsThatCode | 17–21%* | 0.14–0.15* | ~123,000 |

\* WhatsThatCode's "election" algorithm is non-deterministic between runs; range
observed across repeated runs.

## Regex fixes applied after first pass

The first run of CodeSearchNet exposed a real weakness: isolated JS function
bodies (no imports/class syntax) scored only 12.3% (37/300), mostly
misclassified as `cs` or `dart`.

Root cause (found by scoring which regex rules fired):
- `cs`: `\breturn\s+\w+;` (weight 4) — a generic C-like return statement, true
  of nearly any JS/Java/C# function. Fired on 68/300 JS samples wrongly picked
  as `cs`. **Weight dropped 4 -> 1.**
- `dart`: `\b(late|final|const)\s+\w+` (weight 4) — matched bare `const` in JS
  (ES6 `const x = ...`) just as easily as Dart. Fired on 76/300 JS samples
  wrongly picked as `dart`. **Weight dropped 4 -> 1.**
- `sql`: bare keyword match on `FROM`/`JOIN`/`UPDATE`/`WHERE` matched English
  prose in comments and JS method calls (`.join(`, `Buffer.from(`,
  `.update(`). **Added `(?<!\.)...(?!\s*\()` guards** to exclude method-call
  and dotted-access false positives while keeping real SQL clause matches.

Lowering the dart `const/final/late` weight caused a real regression on actual
Dart files in smola/language-dataset (89.5% -> 68.4%, 4 samples flipped): those
files import `dart:*` core libraries (`import 'dart:async';`) rather than
`package:*` libraries, and the only dart-specific import rule required the
`package:` prefix. **Added a `dart:` import rule (weight 6)**, which recovered
Dart accuracy to 94.7% (18/19) — better than before the regression.

Full local test suite (`pytest tests/`, 67 tests) and the original curated
60-sample suite (`benchmark/benchmark.py`) still pass at 100% after these
changes — no regression there.

## Not run: Guesslang

No static downloadable dataset dump exists for Guesslang — only a generator
tool (GuesslangTools) that live-scrapes ~100k GitHub repos, which wasn't
practical to run here. `guesslang` itself is also blocked by the old-TensorFlow
install problem already noted in the main README.

## Remaining known weak spots (not yet addressed)

- `groovy`: 20% on smola (4/20)
- `sh`: 32% on smola (7/22)
- `scala`: 50% on smola (10/20)
- `ts`: 44% on smola (7/16)
- `go` on CodeSearchNet: 75.3% (isolated functions lack `package`/`import`)
- `rb` on CodeSearchNet: 71.0%
